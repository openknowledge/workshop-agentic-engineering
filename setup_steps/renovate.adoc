= Renovate

Renovate hält die Abhängigkeiten des Projekts automatisch aktuell. Der Bot prüft regelmäßig, ob neue Versionen verfügbar sind, und erstellt dafür Merge Requests gegen `develop`. Diese durchlaufen die normale CI Pipeline und werden wie jeder andere MR reviewt und gemergt.

Renovate läuft bei uns nicht als externer Service, sondern als Job in der eigenen GitLab CI Pipeline (via link:https://gitlab.com/renovate-bot/renovate-runner[renovate-runner]).

== Konfiguration (`renovate.json`)

Die Konfiguration liegt im Projekt-Root in `renovate.json`. Die wichtigsten Punkte:

- `config:recommended` als Basis
- Aktivierte Manager: `maven`, `npm`, `dockerfile`, `docker-compose` und `custom.regex`
- `rangeStrategy: bump` für npm, d.h. auch die Versionen in der `package.json` werden angehoben (nicht nur das Lock-File)
- Alle Updates werden in **einem einzigen MR** gebündelt (`groupName: all dependencies`), um die Anzahl der MRs gering zu halten
- Alle MRs erhalten das Label `renovate`

Zusätzlich gibt es Custom Manager (Regex), um Versionen zu erfassen, die Renovate nicht von selbst erkennt:

- Node.js Version im `frontend-maven-plugin` (`basisprojekt-client/pom.xml`) und in der `.nvmrc`
- OpenTelemetry Java Agent, der im `Dockerfile` per `curl` geladen wird (siehe link:monitoring.adoc[Monitoring])
- Docker CLI und Docker Compose Plugin, die in der `.gitlab-ci.yml` im `before_script` heruntergeladen werden

Der Job läuft nur bei geplanten Pipelines (Schedule) oder kann manuell auf `develop` gestartet werden. Die Konfiguration erfolgt über folgende Variablen:

[source,yaml]
.Source: /.gitlab-ci.yml
----
include::../.gitlab-ci.yml[tags=renovate-variables]
----

- `RENOVATE_REPOSITORIES` / `RENOVATE_AUTODISCOVER`: Renovate bearbeitet nur das eigene Projekt
- `RENOVATE_ONBOARDING: "false"`: Kein Onboarding-MR, da `renovate.json` bereits existiert
- `RENOVATE_BASE_BRANCH_PATTERNS`: MRs werden gegen `develop` erstellt (siehe link:git-workflow.adoc[Git Workflow])
- `CI_RENOVATE_IMAGE`: Das `full` Image enthält bereits Node/npm, um Lock-Files zu aktualisieren

NOTE: `RENOVATE_REQUIRE_CONFIG` und `RENOVATE_CONFIG_FILE` sorgen dafür, dass die `renovate.json` aus dem ausgecheckten Branch gelesen wird statt aus dem Default-Branch. Sobald die Konfiguration im Default-Branch liegt, können beide Variablen entfernt werden.

== Einrichtung in GitLab

Damit Renovate laufen kann, müssen folgende Schritte in GitLab manuell vorgenommen werden:

1. **Access Token erstellen**: Unter "Settings > Access tokens" einen Project Access Token anlegen:
    - Name: z.B. `renovate-bot`
    - Role: `Developer` (reicht zum Erstellen von Branches und MRs)
    - Scopes: `api`, `read_repository`, `write_repository`
    - Ablaufdatum notieren, da der Token danach erneuert werden muss
2. **CI/CD Variable anlegen**: Unter "Settings > CI/CD > Variables" die Variable `RENOVATE_TOKEN` mit dem Token als Wert anlegen:
    - Visibility: `Masked`
    - Flags: `Protect variable` nur aktivieren, wenn `develop` ein Protected Branch ist, sonst ist die Variable im Job nicht verfügbar
3. **Pipeline Schedule anlegen**: Unter "Build > Pipeline schedules" einen neuen Schedule erstellen:
    - Description: z.B. `Renovate`
    - Interval Pattern: z.B. `0 6 * * 1-5` (werktags um 6 Uhr)
    - Cron Timezone: `Europe/Berlin`
    - Target branch: `develop`
4. **Optional – `GITHUB_COM_TOKEN`**: Für Abhängigkeiten von `github-releases` (z.B. OpenTelemetry Agent, Docker Compose) fragt Renovate die GitHub API an. Ohne Token greift ein striktes Rate-Limit und es fehlen Release Notes im MR. Dazu einen GitHub Personal Access Token (ohne Scopes) als CI/CD Variable `GITHUB_COM_TOKEN` hinterlegen.

== Renovate manuell ausführen

Zum Testen kann Renovate auch manuell gestartet werden:

1. Unter "Build > Pipelines" auf "Run pipeline" klicken und den Branch `develop` wählen
2. In der gestarteten Pipeline den manuellen `renovate` Job starten

Ob der Token korrekt hinterlegt ist, zeigt die erste Zeile im Job-Log (`RENOVATE_TOKEN present: YES`). Für zusätzliche Optionen (z.B. `--dry-run=full`) kann beim Starten die Variable `RENOVATE_EXTRA_FLAGS` gesetzt werden.
