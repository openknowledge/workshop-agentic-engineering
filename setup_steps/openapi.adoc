= OpenAPI Spec Generation

== Warum OpenAPI?

OpenAPI (früher Swagger) ist eine standardisierte Spezifikation zur Beschreibung von REST-APIs.
Mit **SpringDoc** wird automatisch eine OpenAPI 3.0 Spezifikation aus den Spring MVC Controllern generiert.

Neben der Generierung der Spec werden auch die Bean Validation Annotations in die OpenAPI Spezifikation überführt,
siehe hierzu: <<bean-validation, Bean Validation Constraints in der OpenAPI-Spezifikation>>

== Bean Validation Constraints in der OpenAPI-Spezifikation

=== Herausforderung mit @JsonValue

Bei der Verwendung von Value Objects als Records mit `@JsonValue` entsteht eine Herausforderung:
Bean Validation Annotationen wie `@NotBlank`, `@Size`, `@Email` etc. werden standardmäßig nicht
in die generierte OpenAPI-Spezifikation übertragen.

Das bedeutet: Die Swagger UI würde die Validierungsregeln (z.B. maximale Länge, Pflichtfelder, Format)
nicht anzeigen, obwohl sie im Backend implementiert sind.

=== Lösung: JsonValueConstraintModelConverter

Die Klasse link:../basisprojekt-server/src/main/java/de/openknowledge/baseproject/infrastructure/openapi/JsonValueConstraintModelConverter.java[JsonValueConstraintModelConverter.java]
löst dieses Problem:

Sie ist ein Custom `ModelConverter`, der automatisch Bean Validation Constraints von `@JsonValue`-annotierten
Record-Komponenten ins OpenAPI-Schema überträgt. So werden die Validierungsregeln korrekt in der
Swagger UI angezeigt.

Der Converter unterstützt gängige Bean Validation Constraints wie `@NotBlank`, `@NotNull`, `@Size`,
`@Email`, `@Pattern`, `@Min` und `@Max`.

== Architecture Tests

Die Klasse link:../basisprojekt-server/src/test/java/de/openknowledge/baseproject/architecture/OpenApiConstraintArchitectureTest.java[OpenApiConstraintArchitectureTest.java]
stellt sicher, dass die Validierungsregeln konsistent über alle Schichten hinweg definiert sind.

Der Test validiert:

* Jede `@Column(length=N)` Annotation auf einem String-Feld muss eine entsprechende `@Size(max=N)` Bean Validation Annotation haben
* Jede `@Column(length=N)` Annotation muss mit der tatsächlichen `VARCHAR(N)` Länge in den Flyway-Migrationen übereinstimmen

Dies verhindert Inkonsistenzen zwischen Datenbank-Schema, JPA-Mapping und API-Validierung.

== Verwendung

=== Swagger UI aufrufen

Nach dem Start der Applikation ist die Swagger UI unter folgender URL erreichbar:

----
http://localhost:8080/swagger-ui/index.html
----

=== OpenAPI Spezifikation abrufen

Die maschinenlesbare OpenAPI-Spezifikation ist unter folgenden URLs verfügbar:

**JSON Format:**
----
http://localhost:8080/v3/api-docs
----

**YAML Format:**
----
http://localhost:8080/v3/api-docs.yaml
----
