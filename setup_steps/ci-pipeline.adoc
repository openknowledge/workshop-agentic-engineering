= CI Pipeline

Die CI Pipeline hat folgende Aufgaben:

  1. Bauen der Applikation und Durchführen von Tests
  2. Sicherstellen der Qualität der Applikation
  3. Publizieren des Docker-Images
  4. Automatisches Deployment basierend auf dem Git-Workflow

=== Build Stage

Der `maven-build` Job führt aus:
- Maven Clean Install (`mvn clean install`)
- Kompiliert Java-Backend Code
- Baut und testet Frontend (React/TypeScript mit Vite)
- Lädt Playwright Browser-Binaries herunter für E2E-Tests
- Führt IntegrationTests mit Testcontainers durch

Die Build-Artefakte (Backend JAR, Frontend Assets) werden für eine Woche gecacht und stehen für die nächsten Stages zur Verfügung.

=== Publish Stage

Der `build-docker-image` Job:
- Baut das Docker-Image basierend auf dem Dockerfile
- Tagged das Image mit dem Git Commit SHA
- Pushed das Image in die GitLab Container Registry

=== Deploy Stage

Diese Stage führt zwei Jobs aus, falls der Build erfolgreich war:

. **release Job**: Tagged das Docker-Image mit einem stabilen Tag (`dev` oder `latest`) und pushed es in die Registry
. **deploy Job**: Triggert das eigentliche Deployment via Dokploy API

== Automatisches Deployment

Basierend auf dem definierten Git-Workflow werden Merges automatisch deployed:

- Merges in `develop` → automatisches Deployment auf dev-Umgebung (Tag: `dev`)
- Merges in `main` → automatisches Deployment auf Produktion (Tag: `latest`)
- Andere Branches → kein Deployment

Die Release-Jobs haben folgende Charakteristiken:
- Sie laufen NICHT bei Merge Requests
- Der `deploy` Job hängt vom erfolgreichen `release` Job ab (`needs: release`)
- Sie setzen automatisch die entsprechenden Umgebungsvariablen für Dokploy

== Erforderliche Umgebungsvariablen

Die folgenden GitLab CI/CD Variablen müssen konfiguriert werden:

- `DOKPLOY_DEV_COMPOSE_ID`: ID des Docker Compose Stacks für die dev-Umgebung
- `DOKPLOY_PRODUCTION_COMPOSE_ID`: ID des Docker Compose Stacks für die Produktions-Umgebung
- `DOKPLOY_DEPLOYMENT_KEY`: API Key für Dokploy Deployment Requests

Diese Variablen werden in den GitLab Projekt-Einstellungen unter "CI/CD Variables" konfiguriert.
